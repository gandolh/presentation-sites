# Design system — "The porch notice" (before 2026-11-13: "Ecclesia Digitalis")

The look that ships is described in [DESIGN.md](../../DESIGN.md). This page keeps the token contract and the decisions behind it. The redesign of 2026-11-13 (brief 05) is the section just below; the 2026-06-18 "liturgical rail" section after it is history.

The visual layer of every church site. It lives in `@churchix/ui` and re-skins per church by **token swap only** — components never fork. The design is **reverent, formal, architectural** — a "Digital Iconostasis" that frames sacred content with restraint (tonal layers + 1px outlines over heavy shadows; gold as a sparing accent).

## Source & decision

- **Raw source:** [docs/design/DESIGN.md](../../docs/design/DESIGN.md) (the `Ecclesia Digitalis` token spec) + four reference screens under `docs/design/stitch_churchix_white_label_design_system/` (Home, Program Slujbe, Pomelnice, Donate), generated by Stitch.
- **Decision:** [ADR-0002](../../docs/adr/0002-tailwind-material3-design-system.md) — **adopt Tailwind + the full Material-3 token palette**, superseding [ADR-0001](../../docs/adr/0001-design-system-foundation.md) (which proposed a bounded plain-CSS "safe set"). ADR-0001 was the *brief*; ADR-0002 accepts the *output*.
- **Implementation work:** a design-integration programme of 17 work items brought the system into `@churchix/ui` and the app, built 2026-05-29 and closed 2026-10-07; [log.md](../log.md) has an entry per item. Where it stands: [status](status.md).

## The token contract

- A **Material-3 palette** (~50 color roles: `primary`, `on-primary`, `primary-container`, `secondary`, `surface`, `surface-container-{lowest…highest}`, `outline`, `outline-variant`, `error`, the `*-fixed` set, …), an M3 type scale (`display-lg`, `headline-lg`, `body-md`, `label-md`, `caption`, plus the redesign's `display-xl` and `overline`; Cardo headings with Source Serif 4 as the fallback, Inter body), named spacing (`base/xs/sm/md/lg/xl/gutter/container-max`), and a radius scale.
- Roles are **CSS custom properties** wired into the Tailwind theme (`bg-primary` → `var(--primary)`).
- **Churches set only a small seed set** — `primary`, `secondary` (gold), `surface` (and optional `error`/fonts/radius) — in their `site` content entry ([siteSchema.brand](../../packages/schemas/src/index.ts)). The remaining roles are **derived** in the base layer, not hand-set per church. This preserves ADR-0001's anti-sprawl spirit: the *church-facing* surface stays tiny even though the *system* uses the full palette.
- Brand tokens are emitted as a `:root{…}` block by `BaseLayout` ([packages/ui/src/layouts/BaseLayout.astro](../../packages/ui/src/layouts/BaseLayout.astro)) from the church's content. It outranks the `:where(:root)` defaults in `tokens.css` (see "How the seeds win" below), so a church rebrands by editing content, not code. This is the mechanism behind the [independence-model](independence-model.md).

## Tradition as a variant

v1 ships the **Orthodox** theme (burgundy `#4e0816`/`#6b1f2a`, gold seed `#c8a24b`, warm cream `#fcf9f4`). The same components accept an **evangelical** variant later (warmer palette, sans headings, photography-forward) purely by swapping tokens + the `tradition` flag — no new components. See [traditions](traditions.md).

## Hard constraints (every component)

- **No raw hex / no hardcoded church values** in `packages/*` — always go through a token.
- **WCAG AA** across the realistic token range; gold is decorative, never body text on light.
- **Romanian diacritics** render correctly; layouts survive long DE/RO strings. See [i18n-and-glossary](i18n-and-glossary.md).
- **Astro static-first + React islands**; hydrate only genuinely interactive bits. See [architecture](architecture.md).
- **Money** always shows explicit currency (integer minor units internally). See [donations](donations.md).

## Seed vs derived tokens (the brand contract)

A church re-skins by setting a **small seed set** in `site.brand`; `BaseLayout` emits only those seeds as a `:root{…}` block, and the rest of the ~50 M3 roles are **derived** from them via `color-mix()` in [packages/ui/src/styles/tokens.css](../../packages/ui/src/styles/tokens.css). The same table is mirrored as a comment at the top of that file.

| Seed (church-settable) | `site.brand` field | Derives |
|---|---|---|
| `--primary` (burgundy) | `primary` *(req)* | `--primary-container`, `--on-primary-container`, `--inverse-primary`, `--primary-fixed(+dim)`, `--on-primary-fixed(+variant)`, `--surface-tint`, `--outline-variant` |
| `--secondary` (gold) | `secondary` *(req; was `accent`)* | `--on-secondary`, `--secondary-container`, `--on-secondary-container`, `--secondary-fixed(+dim)`, `--on-secondary-fixed(+variant)` |
| `--surface` (cream) | `surface` *(opt)* | `--background`, `--surface-dim/-bright/-variant`, `--surface-container-{lowest…highest}`, `--on-surface(-variant)`, `--on-background`, `--outline` |
| `--error` | `error` *(opt)* | `--on-error`, `--error-container`, `--on-error-container` |
| `--on-primary` | `onPrimary` *(opt)* | — |
| `--font-heading` / `--font-body` / `--radius` | `fontHeading` / `fontBody` / `radius` *(opt)* | — |

Fixed (not seed-driven): the **tertiary** neutral family + `--inverse-surface`/`--inverse-on-surface` use DESIGN.md literals. `color-mix()` ships in all evergreen browsers (2023+); a church needing pixel-exact tones sets the seed directly — derivation never blocks a build.

**AA contrast (default Orthodox palette, verified):** primary `#4e0816` on cream `#fcf9f4` = 14.6:1; `primary-container #6b1f2a` = 10.8:1; `on-surface` = 16.3:1; `on-surface-variant` = 8.9:1; white-on-primary = 15.3:1; error = 6.2:1 — all pass AA text. **Gold flag:** the church gold seed (`#c8a24b`, the `--secondary` default in `tokens.css`) is only **2.2:1** on cream — it MUST stay decorative (dividers, ≥3px borders, fills behind `on-secondary`), never body text on light. The DESIGN.md token gold `#785a02` passes (6.1) but is darker than the `#c8a24b` seed the audit adopted on 2026-05-30.

## Tailwind `max-w-*` guard

In this theme bare `max-w-sm|md|lg|xl` bind to the spacing scale (`max-w-xl` is 4rem) and collapse layouts; see the note in [theme.css](../../packages/ui/src/styles/theme.css). Use `max-w-2xl` and up, or `max-w-[NNrem]`. `packages/ui/scripts/check-max-w.mjs` fails on a bare class in `.astro`, `.tsx` and `.ts` under `apps/` and `packages/`, and runs in `npm run lint` through the `@churchix/ui` `lint` script. Variants such as `sm:max-w-md` are not flagged. The container itself is `max-w-container-max` (1200px, `--spacing-container-max`).

## Empty-state pattern

Anywhere a list **can render zero items** (announcements, campaigns, schedule, events, gallery), the page must fall back to the shared **`EmptyState`** primitive (`@churchix/ui/components/EmptyState.astro`) rather than rendering an empty container or a bespoke message. This keeps the "graceful degradation" look identical across every church and re-skins by token alone. The pattern:

```astro
---
import EmptyState from '@churchix/ui/components/EmptyState.astro';
import Button from '@churchix/ui/components/Button.astro';
const items = (await getCollection('announcements')).map((e) => e.data);
---
{items.length === 0 ? (
  <EmptyState icon="push_pin" title="Niciun anunț momentan"
              message="Reveniți curând pentru noutățile parohiei.">
    <Button slot="cta" variant="secondary" href="/program">Vezi programul</Button>
  </EmptyState>
) : (
  <AnnouncementList items={items} />
)}
```

Guidance: pick a list-appropriate `icon` (`push_pin`/announcements, `campaign`/campaigns, `schedule`/program, `event`/events), keep the `title` reverent and Romanian, and only attach a `cta` slot when there's a genuinely useful next step. The CTA uses the **secondary** Button variant inside lists (the page already has its primary action elsewhere); list pages own the empty-vs-populated branch, the primitive owns the visuals.

**Error pages reuse the same primitive.** The shared **`ErrorLayout`** (`@churchix/ui/layouts/ErrorLayout.astro`) composes `BaseLayout` chrome (per-church Header/Footer + brand tokens) around an `EmptyState` with a `church`/`diversity_1` illustration, the status code, and a primary "Înapoi la pagina principală" Button (since 2026-11-13 on the slim `PageShell` band, the card raised over its edge). Each app's `src/pages/404.astro` loads its `site` config and renders `<ErrorLayout site={site} />`; reverent Romanian defaults ("Pagina nu a fost găsită") live in the component and are overridable via `title`/`message`/`code`/`icon` props. Astro emits it as a static `404.html` that the CDN/host serves on unknown paths.

**Generic 500 / server-error page is N/A for static SSG.** With the static-per-build deploy target (no Astro adapter), there is no server route to render a `500.astro`; runtime 5xx is handled by the host/CDN, not our code. If a church later adopts an on-demand adapter (the optional escape hatch), it can add a `500.astro` that reuses `ErrorLayout` with `code="500"` and an error-tone message — the composition already supports it.

## Reference-app rollout & visual-QA deviations (2026-05-29)

The one app, `apps/parohia-harlesti-bacau`, is fully on the M3 system; every page (index, program, anunturi list+detail, donatii, pomelnice, contact, despre, 404) uses the shared chrome + primitives. Its brand seeds are `--primary:#6b1f2a` (burgundy) / `--secondary:#c8a24b` (gold). A second reference app (Berinta, blue) existed at the time of the rollout and was removed before 2026-05-30, so the white-label claim now rests on the token chain, not on a second site. Colors flow only through the `text-primary → --color-primary → --primary → :root seed` token chain, so a re-skin is a `site.json` brand edit with **no code change** and no hex in page markup beyond the per-church `:root` seed block.

**How the seeds win (since 2026-11-04).** In a built page `BaseLayout.astro` writes the `:root` seed block in the head before the `<link>` to the stylesheet that carries `tokens.css`. Both are unlayered, so specificity decides, and with equal specificity the later defaults won: until 2026-11-04 every church rendered the default palette. Now `tokens.css` keeps its defaults in `:where(:root)`, which has zero specificity, so the seed block wins whatever the order. We picked this over moving the seeds to `html:root` because the fix sits with the defaults: the seed block stays the plain `:root{…}` every comment and page describes, `theme.css` needs no change, and any later `:root` rule (a church's own stylesheet, say) also beats a default. Tailwind's own `@theme` variables sit in `@layer theme` and still lose to the unlayered defaults. The derived roles are computed on the root element from whichever seed wins there, so they follow the church: the parish reads `--primary` `#6b1f2a` and `--primary-container` `color-mix(in srgb, #6b1f2a 80%, #fff)`. A throwaway second brand (blue primary, green secondary) re-skinned the header CTA, the nav links, the menu toggle, the phone menu's active link and the hero buttons with no browser-side override.

The fix also makes the parish's other brand fields live, such as its `surface` `#faf6ef`. Its `site.json` also carried a leftover `fontHeading` (Source Serif 4, the heading default before Cardo) that would have changed its headings; the owner kept Cardo on 2026-11-04 ([decisions](decisions.md)), so the field is gone and the parish's headings use the system's Cardo.

**Contact** = `SectionHeading` + a parish-data `Card` (`church` icon, `<dl>` with tel/mailto links) + a `Card`-framed `mapEmbedUrl` iframe + a `candle`-icon prayer-request form (`Field` × Nume/Email/Mesaj + primary `Button`). The form is **server-light**: it `mailto:`-submits when the church email is set, else a plain `method=post` placeholder — no backend is assumed (PCI/independence-safe). **Despre** = diacritic-safe `.cx-prose` (line-height 1.75, token-colored `h2`) + an optional **leadership** grid ordered by `staff.order`.

The **`staff`** collection (shared `staffSchema`) is **optional**: registered in the app's `content.config.ts`, seeded with placeholder Preot paroh / Consiliul entries; empty or absent → despre renders prose only.

Intentional deviations from the Stitch reference screens (all reviewed):
- **Prayer-form submit** uses a *trailing* `send` icon; the Stitch pomelnice mock shows a leading icon. Kept trailing to match the Button convention used elsewhere.
- **Despre** has no dedicated Stitch screen — it follows the donate/announcement card+prose language for consistency.
- **Leadership cards** use a `person`-glyph circular avatar placeholder (seed data carries no `photo`); a real photo, when supplied, can replace the glyph later.

## Accessibility (WCAG AA) — contract & audit (2026-05-29)

The system holds **WCAG 2.1 AA** across the realistic brand range. Verified with axe-core 4 (Playwright) on both reference apps' key pages at the time — **0 critical/serious/moderate violations**.

**Contrast contract** (computed for the Harlesti burgundy `#6b1f2a` seed and the Berinta blue `#1e3a5f` seed it was first checked against):

| Pair | Ratio | Use |
| --- | --- | --- |
| `primary` on `surface` | ~10.5:1 | headings, links |
| `on-surface` on `surface` | ~15.8:1 | body |
| `on-surface-variant` on `surface` | ~8.7:1 | muted body/labels |
| `on-primary` on `primary` | ~11.3:1 | buttons, dark bars |
| `secondary-fixed` (gold) on `primary` | ~9.3:1 | Hero eyebrow on dark |
| `on-secondary-container` on the gold chip | ~9.6:1 | Badge/Alert (after fix) |
| `on-primary-container` on the primary chip | ~10:1 | Badge/Alert (after fix) |

**Gold rule (enforced):** `secondary` (gold, ~#c8a24b/#c9a227) is **2.2:1 on cream — never body or label text on a light surface, and never the focus ring on a light surface** (fails WCAG 2.1 AA non-text contrast §1.4.11). Gold appears only as fills, borders, dividers, decorative icons, progress fills, and as *light* `secondary-fixed` text on the dark `primary` Hero. Focus rings on light surfaces use **burgundy `--primary`** (`focus-visible:ring-primary`); gold rings only on the dark hero (where ratio is ~6.4:1). The `on-*-container` "on" tones are derived **dark** (`color-mix(seed 30%, #000)`), per M3 semantics.

**Semantics:** exactly one `<h1>` per page (page title; `SectionHeading as="h1"` / `EmptyState as="h1"` on title-bearing empty/error states), valid heading order (footer section headings are `h2`, the IBAN sub-block `h3`), one `<main>` landmark (provided by `BaseLayout` — pages must not nest their own), `role="progressbar"` + `aria-value*` on the CampaignCard thermometer, labelled form fields with `aria-describedby` hints and `role="alert"`/`aria-live` errors, `aria-current` on the active nav item.

**Keyboard/focus:** a token-driven **skip-to-content** link (`#main`) leads the tab order; every interactive element (nav, language switcher, MobileNav sheet + its focus trap/Esc-restore, CopyIban, donate presets, PomelnicForm, all CTAs, footer links) is reachable with a visible **burgundy `focus-visible:ring-primary`** ring on light surfaces (~14.6:1); gold rings (`ring-secondary`) are used only on the dark burgundy hero where the offset gives ~6.4:1.

**Phone menu** (Base UI `Drawer` since 2026-11-12, `Dialog` from 2026-10-23; since 2026-11-13 it is the `Meniu` place of the `BottomBar`, the sheet rises from the bar and closes on a swipe down; the rest of this paragraph describes the 2026-11-12 build, which hung from the header): `packages/ui/src/islands/MobileNav.tsx` is built on the wrapper `packages/ui/src/primitives/Drawer.tsx` over `@base-ui/react/drawer` (`swipeDirection="up"`), the only file that imports Base UI. The toggle is the trigger and keeps its changing `aria-label`; the sheet is the popup with a hidden title "Meniu", its links in a `<nav>` (`Drawer.Content`). The popup sits in a viewport that is `absolute` in the island's own `relative` wrapper (the portal container), so it still hangs under the toggle. The header has a `backdrop-filter`, which makes it the containing block of a fixed child, so the invisible `Drawer.Backdrop` starts at the header's bottom edge (`top-full`) and catches a tap outside. A swipe up, a tap outside, the toggle (an X when open; the page behind a modal drawer is inert, so a press on it is a press outside), Esc close it, with a short fade and drift under `motion-safe:`. Nav and locale links close it through a `leftByLink` ref, so focus goes where the link went instead of back to the toggle. Base UI also locks the page's scroll, which the hand-built menu never did. The look is pixel-identical to the `Dialog` sheet.

**i18n externalization points:** chrome strings live in `.astro`/island props with RO defaults (nav labels from `site.nav`, `Donează`/locale names/`skipToContentLabel`/`localeLabel` as overridable props); page/content strings come from content collections; money renders via `Intl.NumberFormat` with an **explicit currency** from integer minor units, dates via `Intl.DateTimeFormat`. Liturgical RO terms staying RO inside EN pages is intended, not a defect.

**Long strings:** verbose RO/DE labels wrap (desktop nav is `flex-wrap min-w-0`); IBANs `break-all`; no fixed-width text container clips.
