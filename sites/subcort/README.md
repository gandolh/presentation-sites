# subcort — Subcort

**Demo** presentation site for an **event-tent rental and setup service** in
Gorj / Oltenia: tent brought to the client's own location, mounted to plan,
floored, lit, heated or cooled by season. Romanian, multi-page, static.

Informational by design — [`PRODUCT.md`](PRODUCT.md) records the deliberate
decision that the site carries **no calls-to-action**.

Astro 7 · React 19 islands · Tailwind v4 · Three.js + anime.js + Motion ·
deployed under the sub-path `/subcort`.

## Run it

> This site is an **npm workspace**. Install once from the repo root
> (`npm install` there) — dependencies hoist to the root `node_modules/`, and
> the commands below work from this directory or via the root passthroughs
> (`npm run subcort:dev`).

```bash
npm run dev
npm run build
npm run og          # regenerate the Open Graph card
```

Build for the sub-path the way the VPS serves it:

```bash
PUBLIC_BASE=/subcort npm run build
```

## The visual system

The site is a **drawing set**. [`DESIGN.md`](DESIGN.md) is the full system; the
short version:

- **[`src/lib/draft.ts`](src/lib/draft.ts) owns the model.** One gable marquee,
  in metres, plus the projection and annotation primitives (isometric, dimension
  lines, numbered callouts, flat tonal shading). Every drawing on the site —
  the WebGL hero, the exploded plate, the scale plan, the OG card — comes from
  it. If two drawings ever disagree about the tent, something drew its own
  geometry.
- **The object is ink; every annotation is orange.** That is the whole colour
  system and it is semantic, not decorative.
- **Numbered plates.** A drawing set is a numbered register, so the sections,
  the nav and the footer all carry the same sheet numbers.
- **IBM Plex Sans** for language, **IBM Plex Mono** for every measurement.
- Light throughout, flat, square — depth is line weight, not shadow.

## Imagery

**This site ships no photography.** The only image file is
`public/images/og-image.svg`, generated by
[`scripts/gen-og.mjs`](scripts/gen-og.mjs) from the same model as the pages.
The favicon at `public/favicon.svg` is hand-maintained.

`public/images/real/` exists but is empty and git-ignored. The mock/real
pipeline in [`src/content/images.ts`](src/content/images.ts) is still wired up
via `@sites/kit` so photos could be added later, but nothing resolves through it
except the OG card.

## Motion

- **`HeroScene.astro` + `hero/tent-scene.ts`** — the marquee assembling itself
  out of its exploded layers, in the same order the plate draws them. Built
  entirely from Three.js primitives; panels are explicit corner points rather
  than rotated planes, and fills are flat, shaded by the same `tone()` the SVG
  uses, so the hero and the drawing are the same object rendered twice.
  **anime.js** drives a plain state object through the assembly.
- **`ExplodedPlate.astro`** — the central explanation. Server-rendered SVG with
  a viewBox computed from the geometry, so it needs no JS and can never overflow
  its box.
- **`TentScale.tsx`** — the scale plan on `/corturi`, a React island using
  **Motion**. See the note in that file about why the SVG geometry is written
  imperatively rather than animated through props.
- **`MobileMenu.tsx`** — a React island using Motion, with a focus trap.

Three.js (~127 KB gz) is a dynamic import that only loads for a visitor who has
not asked for reduced motion, has WebGL, and has the hero near the viewport.
Everyone else keeps the isometric still, which is real markup in the HTML.
